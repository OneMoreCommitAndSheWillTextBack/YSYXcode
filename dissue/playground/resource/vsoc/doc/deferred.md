# 暂缓事项 + CDC 讲解（v0.1）

> 这个文件记录"现在**刻意不做**的事"，以及每件事的**触发条件**。写下来是为了将来不在错误的时机做错误的优化。

## 1. CDC 是什么

### 1.1 一句话

CDC = **Clock Domain Crossing（跨时钟域）**：信号从**一个时钟域**传到**另一个时钟域**时，需要专门的处理电路；处理不当会让电路**在硅上偶发错误**，而**仿真里永远看不出来**。

### 1.2 为什么危险：亚稳态

触发器（FF）在时钟上升沿采样 D 端，要求 D 在"建立时间（setup）"和"保持时间（hold）"窗口内稳定。如果 D 正好在这个窗口里翻转（**异步**，即 D 的变化与 clk 无关），FF 的输出会进入**亚稳态（metastability）**：

```
        ┌──── 采样窗口 ────┐
D  ─────┘                   └──────
            ↑ setup  ↑ hold
                       ↑ clk 沿正落在这里 → 输出可能：0 / 1 / 悬在中间电平 / 振荡一会儿再落定
```

后果分三种：

1. **延迟不确定**：输出可能晚一拍甚至晚多拍落定 → 状态机错过事件或重复计数；
2. **不同 bit 落定时刻不同** → 多 bit 数据出现"半新半旧"的组合（**数据撕裂**），比 a=1,b=0 变成 a=0,b=1 这种根本不存在过的值；
3. **MTBF（平均无故障时间）不够**：单靠一个 FF 采样，亚稳态传播概率虽然很低，但系统跑上几小时/几天总会撞上。

### 1.3 标准处理手段

| 场景 | 结构 | 要点 |
| --- | --- | --- |
| **单 bit 电平信号**（slow → fast） | **两级（或三级）同步器**：`ff1 <= d; ff2 <= ff1;` | 至少两拍延迟；第一级任意时刻可能亚稳，第二级把亚稳态"过滤"掉；`ff1`/`ff2` 中间**不允许有任何组合逻辑**（不能写成 `ff2 <= ff1 & x`）；FPGA 上加 `ASYNC_REG` 属性；名字前缀 `sync_` / `_meta` |
| **单 bit 电平信号**（fast → slow） | 同样两级同步器 | 但**要求信号保持足够多拍**（≥ 目标时钟周期/采样周期 + 2），否则会被采丢；快→慢传"窄脉冲"必丢 |
| **单 bit 脉冲** | 脉冲同步器（把脉冲转成电平翻转 → 同步 → 在目标域再恢复成脉冲） | 两个脉冲之间必须有足够的间隔；否则合并成一个 |
| **多 bit 数据（有关联）** | ① **握手**（valid/ack 跨域同步，数据只在稳定期被采样）；② **格雷码指针 + 异步 FIFO**；③ 双口 RAM + 同步指针 | **绝不能**每 bit 各打两拍！每 bit 落定时刻不同 → 撕裂 |
| **异步 FIFO** | 双口 RAM + 格雷码读写指针 + 两级同步器 + 空满判断 | 格雷码保证每次只有 1 bit 变化，同步时不会撕裂；这是"多 bit 跨域"最常用的工业做法，也是面试必考 |
| **复位** | 复位同步器：异步复位 + **同步释放** | 复位**撤销**的边沿也要同步，否则不同 FF 在不同拍退出复位 |
| **时钟切换** | 时钟 mux + 无毛刺切换逻辑 | 更麻烦，本项目不涉及 |

### 1.4 为什么"仿真里永远看不出来"

- Verilator **默认 2-state**（只有 0/1，没有 X），不建模亚稳态；4-state 仿真即使有 X，也需要你在时钟之间加随机相位才可能撞上；
- 所以 CDC 的 bug 有极大概率**在仿真中完全通过**，只在流片/上板后表现为"跑几小时挂一次"或"概率性算错"；
- 真正的 CDC 检查要靠**专用工具**（CDC lint：Spyglass CDC / Questa CDC）或人工审查。这也是"**没有第二个时钟域就别引入 CDC**"的根本原因：引入的成本不在写代码，而在**验证**。

### 1.5 本项目的立场

- 现在全设计**单时钟域**（`clock` 一根），Verilator 也只有一个时钟 → 从定义上不存在 CDC，不需要任何同步器。
- **触发条件**（满足任一条再动手）：出现真实的第二个时钟源，例如：UART 要用真实波特率时钟、接 DDR/SPI/以太网 PHY、做时钟频率切换（DVFS）、上 FPGA 时外部时钟与核时钟不同源。
- 到那时再看回来：所有跨域点都在**模块边界**（`u_soc` 里），用异步 FIFO 放在边界上，内部逻辑保持单时钟域。**别把 CDC 撒进核里。**

## 2. 明确暂缓的清单

| 项 | 为什么现在不做 | 触发条件 |
| --- | --- | --- |
| CDC / 多时钟域 | 见 §1 | 出现第二个真实时钟 |
| 时钟门控 / 电源域 | 综合阶段的事，且会显著增加验证难度 | 有功耗目标 |
| 多 outstanding / ID 路由表 | 核当前只发 1 笔；先做没有收益 | P4（核侧放开） |
| 核侧放开 `hasOlderUnresolvedCfi` / `cfiBlocked` | 依赖 P4 的"无主响应丢弃"能力 | P4 完成后 |
| PLIC / RTC 迁出核 | 核内已经工作，搬迁无收益 | 多中断源 / 要跑 Linux |
| DMA / 外部 master | 只有一个 master 时是纯负担 | 有数据搬运瓶颈 |
| cache 一致性 | 单核无共享 | 多核 / 多 master 共享内存 |
| 真 UART（RX/中断/波特率） | 当前只用 TX 打字符 | AM 用例需要输入或中断 |
| 波形/覆盖率基础设施 | host 侧已有 `npc_wave`；增量不大 | 调试需求出现 |
| 综合流程对齐（`ysyxSoC` blackbox 名统一等） | 与仿真性能优化无关 | 要上板/流片 |
| UART 走 DPI 输出（`vsoc_uart_tx`） | `$write` 已经够用，加 DPI 要动 host | 需要 host 捕获/重定向字符流 |
